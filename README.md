# まんぞうラブ（Mangumi）

YouTuberグループ「マン組」のファン向け公式アプリと運営管理画面を開発するリポジトリです。
初回リリースはWebアプリ／PWAとし、その後iOS・Androidへ展開します。

## 開発状況

Expo SDK 57・Expo Routerで、サイトマップの**利用者109項目・管理95項目、合計204項目**を実装したWeb／PWAのUIプレビューです。画面、例外状態、確認モーダル、共通部品を含みます。

UI案は画面構成の根拠、別途提供された「雰囲気イメージ」は全ページのビジュアルの基準として使用しています。ゴールドの金属フレーム、赤いランプ、ネオン、リール、音を利用者・管理の全画面に適用しています。

管理画面の予定・通知・ストーリー編集は同じブラウザセッションの利用者画面へ反映されます。DM、通報、問い合わせ、チケット抽選、コレクション、CSV、監査履歴もプレビュー内で操作できます。

**本番API、DB、メール、Web Push配信、LiveKit、Stripe、ストア課金は未接続です。** 認証は画面フローのプレビューで、実際のアカウント作成・決済・外部メッセージ配信は行いません。サンプルデータを使う本番公開前のUI実装です。

## 起動と画面確認

Node.js 24、pnpm 11で開発しています。

```powershell
pnpm install
pnpm dev
```

開発サーバーは `http://localhost:8081` です。静的ビルドを確認する場合：

```powershell
pnpm build
pnpm preview
```

プレビューは `http://localhost:4173` です。

Windowsでは、サーバー停止時に `StartPreview.cmd` をダブルクリックして起動できます。確認中は起動したウィンドウを開いたままにしてください。この起動方法はCodexの実行セッションに依存せず、ローカルのNode.jsまたはCodex同梱のNode.jsを使用します。

| URL                                                       | 内容                                            |
| --------------------------------------------------------- | ----------------------------------------------- |
| `/`                                                       | 利用者ホーム                                    |
| `/calendar`・`/stories`・`/space`・`/dm`・`/gacha`・`/me` | 各機能の入口                                    |
| `/admin`                                                  | 管理ダッシュボード                              |
| `/screens`                                                | 全204項目の検索・一覧、プレビューデータの初期化 |
| `/u/U001`〜`/u/U109`                                      | 利用者の個別画面・状態                          |
| `/admin/A001`〜`/admin/A095`                              | 管理の個別画面・状態                            |

効果音は初期OFFで、操作によりONにできます。ランプ、光沢、画面の登場、波形、リール、紙吹雪を実装し、「演出ひかえめ」とOSの動きを減らす設定を尊重します。

サンプルデータは `sessionStorage`、音と演出の好みは `localStorage` に保存します。パスワード、カード番号、CVCは保存しません。録音音声は端末のメモリ内でプレビューします。

現在の描画はWebのDOM／CSSです。共有TypeScriptモデルと操作ロジックへ、将来のiOS・Android版の描画、通知、ストア課金アダプターを追加する計画です。

## プロダクト方針

- 登録直後は全員をFreeプランに所属させ、初期公開ではFreeプランのみ有効にします。
- 各機能の利用可否、権限、利用上限をプランごとに設定し、画面とAPIの両方で判定します。
- 利用者アプリと管理画面を同じPWAに実装し、認証、型定義、API、デザイン要素を共通化します。
- 日常的に変更する設定値、公開状態、対象プラン、通知タイミングなどを管理画面から操作できるようにします。
- PWAのインストール案内と、利用者のボタン操作による通知許可フローを用意します。
- DMや音声ルームなどには、通報、ブロック、モデレーション、利用停止を組み込みます。
- 管理操作、権限変更、返金、抽選設定変更を監査ログに記録します。

## 初回リリースの範囲

### 利用者アプリ

- 会員登録、規約同意、メール確認、ログイン、パスワード再設定
- プロフィールとログイン中端末の管理
- 端末・ブラウザに応じた画像付きPWAインストール案内
- 配信予定の月／週／一覧表示、予定詳細、外部配信リンク
- Web Pushの端末登録、配信リマインド、通知種別・時間帯の設定
- Freeプランと機能権限の適用

利用者画面は、PC・タブレットでも最大幅460pxを基準とする縦長UIを中央に表示します。
共通ナビゲーションは「ホーム」「予定」「スペース」「DM」「マイページ」を想定し、未公開の機能は非表示またはロック表示にします。

### 運営管理画面

- 管理者専用ログイン、二要素認証、ロールベースの権限管理
- 会員検索、プラン設定、機能割当、利用停止、セッション失効
- 配信予定の登録・変更・中止、通知の即時送信・予約・結果確認
- ロゴ、アイコン、テーマ色、PWA案内画像などのブランド設定
- 管理操作の監査ログ

管理画面は320px程度の画面幅からデスクトップまで対応します。
管理ロールはスーパー管理者、コンテンツ管理者、モデレーター、サポート担当、経理担当を想定します。

## 技術構成（仕様書の採用案）

| 領域         | 構成                                                                             |
| ------------ | -------------------------------------------------------------------------------- |
| 利用者アプリ | Expo、React Native、React Native Web、Expo Router、TypeScript                    |
| 管理画面     | 同じPWA内の管理者専用ルート、React Native Web、TypeScript                        |
| PWA          | Web App Manifest、Service Worker、標準Web Push API、VAPID                        |
| API          | Fastify、TypeScript、REST API、OpenAPI                                           |
| データベース | 本番はMariaDB、開発はSQLite                                                      |
| 通知ジョブ   | DBのジョブテーブルをAPIプロセス内で定期ポーリング。Redisは使用しない             |
| ファイル     | 開発はローカルファイル、本番はVPSの永続ボリュームと別のバックアップ先            |
| 音声ルーム   | LiveKitなどのWebRTC SFU。通常のAPI／DBホストから分離                             |
| 決済         | Web版はStripeを候補とし、将来のネイティブ版はStoreKit／Google Play Billingへ対応 |
| メール       | トランザクションメールサービス                                                   |
| 本番環境     | さくらVPS、Caddy、コンテナ構成                                                   |

音声基盤、決済、メールなどの外部サービスと本番のサーバーサイズは、実装・検証時に確定します。

## 実装で守る条件

- メール未確認の会員は保護機能を利用できないようにします。
- WebのセッションにはSecure、HttpOnly、SameSite属性付きCookieを基本とし、パスワードはArgon2idでハッシュ化します。
- 管理者には二要素認証を必須とし、操作ごとの権限判定と監査を行います。
- 認証情報、DM、決済、ガチャ結果をオフラインキャッシュに保存しません。
- カード番号とCVCを保存せず、決済結果は署名検証済みWebhookで確定します。
- 決済、抽選、通知予約の二重処理を防ぎます。
- 初期のDMは一般会員と公式配信者の1対1に限定し、音声ルームの録音は無効にします。
- ガチャは無料チケット方式から開始する案とし、公開確率の履歴を保持します。
- 日時はUTC、金額は最小通貨単位の整数で保存します。

## 実装の進め方

1. ブランド、DM範囲、年齢方針、規約の責任者を確定する。
2. モノレポ、認証、DB、管理者権限、監査ログを構築する。
3. PWA、インストール案内、会員登録、メール確認を完成させる。
4. 配信予定、通知ジョブ、Web Push、管理画面を完成させる。
5. Phase 1の実機、負荷、復旧、セキュリティ試験を行う。
6. ストーリー、DM、音声ルームを段階的に追加する。
7. 決済とガチャは、提供条件・法務・会計・ストア方針を確定してから有効化する。

年齢制限、有料プランの名称・価格、投げ銭の上限、音声ルームの最大人数、退会後のデータ保持期間などの未確定事項は、[仕様書の「運用開始前に決める事項」](docs/product-specification.md#運用開始前に決める事項)で管理します。
